# Review checklist: Experiment Readiness and Evidence

**Feature**: [spec.md](../spec.md)

This checklist records acceptance obligations, not a claim of runtime completion.

- [ ] Retained readiness/configuration/evidence IDs have one current owner.
- [ ] Selected adapter/configuration identifies real versus fixture/scaffolding paths.
- [ ] Positive and blocked readiness cases do not use Git, registry or source trees.
- [ ] Required connection/capability/credential/input failures are explicit.
- [ ] Caller-owned preparation is separate from read-only readiness checks.
- [ ] Supplied/observed provenance and missing revisions are represented accurately.
- [ ] Metadata is versioned and uses canonical OTel GenAI names.
- [ ] Record-level evidence and review rationale support validation claims.
- [ ] A copied run packet regenerates offline without original inputs or services.
- [ ] Secrets/private reasoning remain excluded; clinical publication is reviewed.
- [ ] Real product/deployed acceptance is distinct from test-double mechanics.
- [ ] Runtime verification evidence is recorded in Feature 006's plan.
