## Findings and resolutions

The three Spark findings below are retained as the initial review record. Their code fixes are present on the current published heads; the required live Spark acceptance remains open.

### 1. Comparison commands failed before a run started — resolved

**Resolved on harness #100 at `9d67fbb`.** The initial snapshot at `2cf3de8` showed every comparison command calling a configuration helper that imported the deleted `postgres_dsn` function. Importing that symbol reproduced `ImportError`; even reading `outputDir` took this path, so `run`, `resume`, `prepare-review`, and `finish` failed before doing their work. [Initial launcher evidence](https://github.com/pmanko/clinical-ai-validation-harness/blob/2cf3de847e9dd6f5b1f0ae3ce5ff8e49c36a52ba/scripts/catalyst-comparison.sh#L25).

The obsolete import is removed on the published harness head. A fresh comparison still needs to run against the selected Spark source; earlier Python tests and the historical HIV demo do not establish that live acceptance.

### 2. The two configured sources shared one Spark database — resolved in configuration

**Resolved on the current published heads.** The initial snapshot recorded both controllers registering views in `default`, while both Catalyst source connections selected that namespace. Only HIV had been ingested, both labels exposed the same 24 relations, and another ingestion could replace overlapping view names. [Recorded initial collision and remedy](https://github.com/pmanko/clinical-ai-validation-harness/blob/2cf3de847e9dd6f5b1f0ae3ce5ff8e49c36a52ba/specs/artifacts/findings/two-sources-share-one-spark-namespace.md).

The current configuration isolates the `openmrs_hiv` catalog. Live multi-source ingestion has not been rerun, so this is not a claim of live acceptance.

### 3. Superset export compiled PostgreSQL literals for Spark — resolved

**Resolved on Catalyst #79 at `d4a2368` with regression coverage.** The initial snapshot showed the Spark branch changing the export connection to Hive/Spark while the parameter compiler emitted `TIMESTAMPTZ '2026-09-06T12:00:00Z'` and left string backslashes unchanged. [Initial compiler evidence](https://github.com/DIGI-UW/openelis-catalyst/blob/ce07504bcd7cb295527e62df6b12586b127f2c1b/catalyst-gateway/src/catalyst/dashboard_builder.py#L123) documented the incompatibility.

The current branch makes the export compiler honor the selected dialect and includes focused coverage. The generated statements have not been executed against a live Spark server in this review, so this does not accept the complete Dashboard Builder phase.

### 4. ChartSearchAI can emit a second terminal event after a transport failure

**Resolved on the current PR head.** In the initial PR snapshot, the provider's exception path treated an existing answer as recoverable success without checking whether a terminal success or error was already emitted. A read or close failure after the terminal event could therefore emit another `TURN_DONE`, and an earlier terminal error could become a successful returned result. The current branch preserves the first terminal outcome and has regression coverage for both cases.

A probe compiled the unmodified PR classes and exercised their existing transport interface:

| Input sequence before transport throws | Observed terminal events | Returned result |
| --- | --- | --- |
| answer_done → done | TURN_DONE, TURN_DONE | Success |
| answer_done → error | TURN_ERROR, TURN_DONE | Success |

The repository's lifecycle validator reports “a turn must contain exactly one terminal event” in both cases. Preserve the terminal outcome before applying interrupted-answer recovery, and cover exceptions after both success and error. Existing review fixes ignore later wire messages; they do not cover this exception path.
