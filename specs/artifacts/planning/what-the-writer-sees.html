Catalyst · context engineering — practices, evidence, roadmap

What the Writer Sees

The practices the field converged on for accumulating, session-persistent context; the evidence behind each; and a deliberately lean roadmap for Catalyst — every lever run as a cheap experiment first, validated by an evaluation harness, and hardened only if the numbers say so.

Experiment before contract

Every lever ships first as the cheapest thing that can move a metric — a field, a flag, a script. Contracts, UI, and governance harden a lever only after it has earned its keep.

Nothing new to operate

No new services, stores, or models. Every proposal below is a bounded change to the gateway request, the ingestion SQL, or a script over records the system already writes.

The harness decides

This is an exploratory project feeding future production designs. What survives is what a measured baseline-vs-lever comparison keeps — not what sounded architectural.

Owner decision

One reviewed 13-relation surface for the writer, editor, validator, and executor.

Qualification

Compare the completed system across three model teams locally; do not claim an individual context practice caused the result.

Deployment proof

Run three real browser journeys on the server after the local comparison.

Three structural contradictions

Grammar vs prompt
The prompt commands “ask for clarification rather than inventing”; the grammar pins status:"ready". The writer structurally cannot ask.
Catalog subset
Generation ⊂ execution, silently. Humans can query what the model is never told exists.
Names dropped
hiv_patient_dim_v1 = SELECT DISTINCT id, gender, birth_date — names were casualties of a dedup shortcut during ingestion setup, and the dim sits outside comment coverage anyway.

Recorded but never reaching the model

Failed-turn findings · retained near-miss attempts · prior turns' SQL and outcomes · human corrections as durable facts (turn 2's “gender is labeled as last name” was in turn 3's history and changed nothing) · human-verified queries. All digest-bound, all already stored — the substrate is unusually good; only the delivery is missing.

P1 · Semantic grounding materially affects accuracy

strong, quantified
Claim
Business meaning attached to the schema (descriptions, grain, synonyms) can materially improve accuracy and must be measured on Catalyst's workload.
Evidence
The two chart groups above: a 70-point cliff without grounding; an 8–16-point lift with it, on frontier models.
Catalyst fit
Mechanism already built (COMMENT ON → catalog); the lever is coverage + scope. → CE1

P2 · Accumulate as an itemized playbook, never a summary

strong, benchmarked
Claim
Improving contexts are discrete, provenance-carrying entries, appended and refined incrementally — never rewritten wholesale or compressed to prose.
Evidence
ACE: +10.6pp/+8.6pp, and names the failure modes to design against — brevity bias (summaries drop the detail that mattered) and context collapse (rewriting erodes knowledge). Anthropic converges from practice: structured notes outside the window, pulled back when relevant.
Catalyst fit
The notebook already is this shape — see §03. → CE2

P3 · Verified-query exemplars

strong; product-grade adoption
Claim
Retrieving human-verified question→SQL pairs for similar questions is a promising accuracy lever that Catalyst must qualify rather than assume.
Evidence
Shipped as a core primitive in Snowflake Cortex Analyst (VQR); standard across production stacks. Enterprise practice: feedback-loop teams keep improving, one-time setups plateau.
Catalyst fit
Every hand-edited → run → kept version is already a recorded golden pair. Nothing retrieves them. → CE4

P4 · Correction needs the error in context

strong, replicated
Claim
Models fix SQL reliably only when the failed attempt + concrete error + a plan are in the next request; unguided self-critique plateaus.
Evidence
SQL-of-Thought (guided error correction converges), MTSQL-R1 (dialogue memory required over long horizons), DySQL-Bench (measures the degradation). We watched the counterfactual live: the same instruction re-entered cold and died the same way, repeatedly.
Catalyst fit
WS7 routes findings to the human; nothing routes them to the model. → CE3

P5 · Clarification as a first-class model move

directional, converging
Claim
When a request can't be grounded, letting the model ask beats forcing a guess — and conversation mode is impossible without it.
Evidence
Ambiguity handling is a scored dimension in recent multi-turn benchmarks; product systems route unanswerable questions instead of forcing SQL. No single headline number — exactly the kind of claim CE0 measures on our workload before we trust it.
Catalyst fit
Contract, WS7 gateway classification, and UI all exist. Only the writer grammar forbids it. → CE1

P6 · Context mechanics: append-only, stable prefixes, bounded blocks

strong, operational
Claim
Order context stable-first and append-only; keep per-step context minimal; every added block is capped and honest about omissions.
Evidence
Manus production data: 10× cached-vs-uncached token cost; single-token prefix changes invalidate the cache. Anthropic: just-in-time over pre-loading.
Catalyst fit
A design constraint across CE2–CE4, not a workstream — visible in the “Proposed” column above.

CE0 · gate

Evaluation harness — a script over records the system already writes. Nothing ships unmeasured; without it every claim below is opinion.

CE1S
Honest writer's world: catalog decision, names gap, writer may ask.
CE3S–M
Failure fed back: last attempt + findings in the retry request.
CE2M
Session playbook: pinned guidance entries in every request.
CE4M
Verified exemplars: session-scoped few-shot first, retrieval later.

Deliberately not building (the overengineering line)

  • No vector database, embedding service, or retrieval infra — CE4 phase 1 is “this session's kept turns”, a list comprehension.
  • No automated Reflector/Curator — the human pins; automation waits until manual entries show what good looks like and CE0 can score it.
  • No cross-session or cross-user memory — governance questions deferred until session-scoped accumulation proves value.
  • No summarization/compaction of guidance — entries verbatim; caps + omission records, per ACE's failure modes.
  • No new services or stores — session-attached data in the existing SQLite store; scripts in the existing repos.
  • No speculative conversation mode — CE1–CE3 are its prerequisites; the mode itself waits until they're measured.

CE0 — Evaluation harness

the gate · size M
Form
Extend the existing notebook-validation runner with the frozen 12-scenario, 21-turn suite, arbitrary turn sequences, one measurement per team/scenario in each complete run, and three complete suite runs. Extend the unchanged batch to five only when a scored turn varies in outcome/correctness, a leave-one-run-out score changes qualification, or the leading teams differ by at most one complete-scenario success out of 36. Retain exact token evidence, separate infrastructure failures, and byte-stable scoring replay.
Substrate
Already recorded: every turn's evidence bundle holds the exact hub request, per-attempt raw outputs, findings, digests. Golden results come from human-verified runs.
Metrics
Execution accuracy vs golden digest · first-attempt candidate rate · attempts-to-success · grounding-failure rate (invented identifiers) · clarification precision/recall · tokens + latency.
Acceptance
One consolidated local report across writer-only, same-family-check, and cross-family-check teams; three deployed browser journeys after selection.

CE1 — Honest writer's world

P1 + P5 · size S · first lever
Form
One reviewed list of all 13 readable relations for generation, editing, validation, and execution; complete data meaning and join-risk notes; safe patient-name components; ready, needs_clarification, and unsupported writer branches.
Validate
Exact catalog/grant equality, safe read-only behavior, independent database answers, honest clarification, and unsupported requests that never reach SQL.
Contract
Published catalog v6 remains historical evidence. Catalog v7 records the corrected 13-relation decision. Runtime permissions never auto-publish a relation.

CE2 — Session playbook

P2 + P6 · size M · the core capability
Form
A versioned guidance list on the existing session store, composer pin, explicit pin-from-failure, append-only unpin/supersede, and verbatim delivery. Model-facing entry = {text, source, originTurnId, createdAt}.
Validate
Pin at turn k; later turns honor it without repetition. Prove exact text, provenance, restart survival, session isolation, 20-entry capacity, token limits, literal rendering, and honest omissions.
Contract
The same object becomes P2 conversation state; successful queries remain verified examples rather than guidance.

CE3 — Failure fed back

P4 · size S–M · completes WS7's loop
Cheapest form
When the prior turn on this intent failed, add a bounded previousAttempt block to the revision context: the retained SQL, unresolved finding codes + evidence, and the human's clarification answer if any. One prompt paragraph explains the block.
Validate
Only the most recent relevant failure in the current revision line is delivered; first attempts and unrelated turns receive none; retained SQL, finding evidence, and any clarification answer remain digest-bound.
Contract
One bounded block with the same token, omission, and session-isolation rules as guidance.

CE4 — Verified-query exemplars

P3 · size M · free substrate
Form
Session-scoped successful kept turns only, matching source and catalog; deterministic word-overlap ranking; at most three; no retrieval service.
Validate
The CD4 near-neighbor case is correct while the unrelated visit question never copies the example. A target can never receive itself.
Contract
Cross-session retrieval remains outside Phase 1.

Deferred to the larger session

explicitly out of scope now
  • Repair-loop redesign — anchored patches vs full regeneration, attempt budgets. Needs a later controlled study; the patch machinery manufactured several failures we watched.
  • Automated reflection/curation (full ACE) — after CE2's manual channel shows what good entries look like.
  • Cross-session / cross-user promotion — whose lesson, verified by whom.
  • Generic metadata generation — FHIR-spec-derived semantics for flat columns (auto-description research); worth it when the approved set outgrows hand-commenting.
  • Causal model claims — the three complete teams are compared, but this run does not isolate reviewer or quantization effects.
